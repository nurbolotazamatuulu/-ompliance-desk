# Инструкции для Claude Code

Ты реализуешь **ComplianceDesk** — регуляторный терминал для VASP-комплаенс Кыргызстана. Дизайн полностью определён; твоя задача — превратить его в рабочее React+TS+Tailwind приложение.

## Правила

1. **Не импровизируй визуальный язык.** Цвета, типографика, отступы — строго из `starter/src/styles/tokens.css`. Не добавляй свои hex/oklch.
2. **Стек фиксирован.** React 18 + TypeScript + Vite + Tailwind 3 + React Router 6 + Lucide. Состояние — Zustand. Формы — React Hook Form + Zod.
3. **Структура папок** — см. `spec/architecture.md`. Не отклоняйся.
4. **Типы данных** — единственный источник `spec/data-model.ts`. Скопируй в `src/types/` и используй везде.
5. **Мок-данные** — `spec/mock-data.ts`. Скопируй в `src/mocks/`. Все списки заполняй из этого файла, на 100+ строк.
6. **Иконки** — только Lucide. Маппинг смыслов в `spec/icons.md`.
7. **Темы** — переключаются атрибутом `data-theme="dark"|"light"` на `<html>`. Пользовательский выбор — в localStorage `cd:theme`.
8. **Все строки на русском.** Без эмодзи, без англицизмов в UI.
9. **Доступность** — все интерактивные элементы с `aria-label`, фокус-видимый, навигация Tab. Контраст AA как минимум.
10. **Не ломай токены под конкретный кейс.** Если кажется, что нужен новый цвет — спроси.

## Порядок работы

Иди по этапам из README. На каждом этапе:

1. Прочитай нужные файлы из `spec/` и `components-ref/`.
2. Сгенерируй компоненты с TypeScript-типами и пропсами как в `spec/components.md`.
3. Подключи к роутеру.
4. Покажи результат с мок-данными.
5. Реализуй состояния (empty/loading/error) — паттерны в `spec/states.md`.
6. Только потом переходи к следующему этапу.

## Пиксельная сверка

В `components-ref/` лежат куски JSX из визуального прототипа. Они показывают:
- какие отступы между элементами,
- какой размер шрифта на каком уровне,
- как выглядят бейджи риска, KYT-флаги, дельты,
- как устроена шапка с метриками риска.

Не копируй inline-стили буквально — переноси в Tailwind-классы по таблице соответствий в `spec/components.md` § «Inline → Tailwind».

## Что должно работать

- Навигация между всеми экранами (клик по строке клиента → карточка).
- Поиск и фильтры в реестре клиентов.
- Переключение тем dark/light.
- Все 7 вкладок карточки клиента отображаются (контент может быть мок).
- Wizard онбординга ЮЛ/ФЛ — переходы между шагами с валидацией.

## Что не нужно делать

- Реальный бэкенд. Все данные — из моков; имитируй задержки `setTimeout` 300–800мс.
- Реальную крипто-интеграцию. KYT-граф рисуется на статичных данных.
- Multi-tenant, биллинг, settings выше необходимого.

## Где брать вопросы

Если в спеке что-то противоречит или непонятно — оставь TODO-комментарий в коде с пометкой `// TODO(spec): …` и продолжай. Не выдумывай.
