## KPI-карточки

Компонент `KPICard` (новый):
- Лейбл `cd-caps`.
- Значение `text-3xl font-mono` в цвет (нейтральный/orange/red).
- Дельта снизу: `+6 за 7д ↑` мелкими (text-xs mono).
- Слева тонкая 2px вертикальная линия в цвет tone.

Tone-логика:
| Метрика | Условие |
|---|---|
| В работе | neutral |
| Новые сегодня | blue |
| SLA-риск | orange если >0 |
| Critical | red если >0, иначе neutral |

Клик по карточке → перейти в `/clients` с пред-фильтром.

## Очередь дня (DataTable)

Колонки:
1. `#` — № в очереди (mono).
2. `Клиент` — fileNumber + имя/название (mono small + обычный).
3. `Тип` — бейдж ФЛ/ЮЛ.
4. `Риск` — бейдж уровня + балл mono.
5. `SLA` — мини-progress + «2д 4ч» mono. <12ч — orange, <4ч — red.
6. `Статус` — `<ClientStatusBadge>`.
7. `Назначен` — имя офицера.
8. `Триггеры` — счётчик KYT/санкций (chip).

Строка clickable → `/clients/:id`.
`rowTone`: critical — red фон; SLA <4ч — orange.

## Лента событий

3 таба с локальным state (без роутинга): «Санкции» (default), «KYT-флаги», «Документы».
Каждая карточка-событие:
- Иконка слева (Lucide по типу).
- Заголовок: «Совпадение в OFAC SDN — Сходство 92%».
- Подзаголовок mono: «ОсОО "Бишкек Крипто Брокер" · 14:32».
- Кнопка «Открыть» справа.

Лимит 8 карточек, кнопка «Показать все 47» внизу → `/sanctions` etc.

## Распределение риска

`<RiskDistribution>` — донат 4 сегмента (low/med/high/crit), легенда справа со счётчиками.
Нажатие на сегмент → переход в `/clients?risk=high`.

## Состояния

- **Loading** — KPI-карточки skeleton; таблица skeleton-rows; лента skeleton.
- **Empty (новый аккаунт)** — большой EmptyState «Очередь пуста — все заявки разобраны». Иконка `CircleCheck` green.
- **Error** — каждая секция независимо может упасть и показать «Не удалось загрузить» + retry.

## Адаптив
