# 06 · Админка

**Роут:** `/admin/*`
**Роли:** только `admin`.

## Под-разделы (вторичная нав)

```
/admin/users        Пользователи
/admin/roles        Роли и права
/admin/audit        Аудит-лог
/admin/scoring      Конфигурация скоринга
/admin/sanctions-lists   Источники санкций
/admin/integrations Интеграции (KYT-фиды, OTP-провайдер, e-Signature)
/admin/settings     Общие настройки
```

Под-навигация — горизонтальные табы под Header.

## Пользователи

DataTable: ФИО, e-mail, роль, активен, последний вход, создан.
Toolbar: поиск, фильтр по роли, кнопка «+ Создать».
Создание/редактирование — Drawer 520px с формой.

## Роли и права

Левая колонка — список ролей; правая — матрица permissions:
- Строки: ресурсы (Клиенты, Транзакции, Санкции, Документы, Админка, …).
- Колонки: действия (View, Create, Edit, Delete, Approve, Override).
- Чекбоксы. Сохранение по кнопке «Применить» (с тостом «Изменения вступают в силу немедленно»).

## Аудит-лог

DataTable, виртуализация, экспорт CSV. Фильтры: actor, тип события, период, ресурс. Клик по строке → Drawer с full detail (`before/after` JSON-diff).

## Конфигурация скоринга

Список правил по 4 категориям. Каждое — карточка:
- Код mono.
- Название.
- Вес (slider 0–100).
- «Override-триггер» (toggle).
- «Активно» (toggle).

Сверху — превью «Сейчас при пересчёте всех клиентов изменится 87 баллов в среднем на ±5,4».

## Источники санкций

Список фидов с расписанием синхронизации, статусом последней проверки, кнопками «Синхронизировать сейчас» и «Включить/выключить».

## Интеграции

Карточки интеграций:
- KYT-фид (Chainalysis / TRM Labs / самописный) — статус подключения.
- OTP-провайдер.
- E-Signature.
- Object Storage.

## Настройки

- Бренд (загрузка логотипа на отчёты).
- SLA-таргеты по типам клиентов.
- Период хранения аудит-лога.
- Локали и форматы.

## Состояния

- Все CRUD — оптимистичное обновление + откат на ошибке.
- Mass-actions — confirm-диалог.
- Любое разрушительное действие — двойное подтверждение (введи кодовое слово / ИНН клиента).
