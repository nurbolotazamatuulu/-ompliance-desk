# 07 · Конструктор УБО

**Роут:** встроенный (вкладка карточки клиента + шаг 7 онбординга ЮЛ).

## Цель

Построить и провалидировать структуру конечных бенефициарных собственников. Поддержка как прямого, так и непрямого владения через цепочки ЮЛ.

## Лейаут (вкладка карточки)

Под-табы «Структура» (граф) / «Список» (таблица).
Toolbar: «+ Добавить узел», «Импорт из ЕГРЮЛ» (placeholder), «Валидировать».

## Граф

`reactflow` (или равноценный) с кастомными нодами:
- **ClientNode** — корневой клиент. Нелдвижимый, в центре сверху.
- **EntityNode** — юрлицо в цепочке владения. Прямоугольник, mono ИНН, наименование, страна, доля.
- **PersonNode** — физлицо-бенефициар. Скруглённый прямоугольник, ФИО, ИНН, гражданство, доля, PEP-флажок.
- **Edge** — стрелка снизу вверх, лейбл «X%», цвет в зависимости от прямого/непрямого владения.

Drag-create: тащим из палитры справа. На клик ноды — Drawer с формой редактирования.

## Список (табличный вид)

DataTable:
- ФИО / Наименование
- Тип (ФЛ/ЮЛ)
- ИНН
- Гражданство/страна
- Доля прямая %
- Доля эффективная % (расчётная по графу)
- Контроль (basis)
- PEP

## Валидации

- Сумма прямых долей по каждому узлу = 100%.
- Эффективные доли всех ФЛ-бенефициаров суммарно = 100%.
- Не должно быть циклов в графе.
- Каждое ФЛ ≥ 25% — обязательное «существенное участие».
- При ИНН KG — формат 14 цифр.

Кнопка «Валидировать» прогоняет правила и подсвечивает проблемные узлы красным с tooltip.

## Состояния

- **Empty** — большой EmptyState «Бенефициары не указаны» + кнопка «+ Добавить ФЛ» / «+ Добавить ЮЛ».
- **Invalid graph** — баннер сверху red «3 ошибки в структуре» + список с переходом к узлам.
- **Loading** — skeleton-граф (3 серых блока).

## Адаптив

Граф — desktop only. На tablet/mobile показываем только список + предупреждение «Редактирование графа доступно на десктопе».
